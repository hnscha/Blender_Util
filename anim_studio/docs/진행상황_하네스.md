# Anim Studio 진행상황 하네스

> 다음 작업자가 이 파일만 읽고 이어갈 수 있게 남기는 기록. 수정·추가 전에 먼저 읽는다.
> 기준: 2026-11-22. Blender 5.2.2 LTS. 구현 = Codex, 검증·커밋 = Claude(HS "커밋" 후).

**핵심 3줄**
- 0단계(뼈대 + 공통 엔진 4개 + 단축키 묶음)는 00 → 00b → 00c 까지 구현·검증 완료. 00d 는 1~5번까지 코드·테스트 통과, 6번(아이콘 연결)은 미완.
- 리그 계산이 맞는지는 실제 Rig Studio 리그로 잰다. 가짜 메타데이터 테스트만으로는 못 잡는 문제가 있었다(미러 짝 중복).
- Rig Studio 리그는 **현재 FK/IK 모드 컨트롤에만** 쓴다. 반대 모드 컨트롤을 건드리면 Rig Studio 자동 매칭이 끼어든다.

## 3. 규칙 (어기면 반려)

- 위치는 `Blender_Util\anim_studio\` 만. 다른 애드온·Blender_Rig 는 읽기만.
- 리그에 드라이버·컨스트레인트를 영구히 더하지 않는다. 시간·핸들러로 계속 도는 동작 금지(`load_post` 정리 1개만).
- 데이터를 바꾸는 오퍼레이터 = `{'REGISTER','UNDO'}`, 화면만 바꾸는 오퍼레이터 = `{'REGISTER'}`.
- 액션 F-커브는 5.x 레이어드 API(slot → channelbag). `action.fcurves` 금지.
- 한 프레임 키 쓰기·지우기 전후로 **키 안 찍은 현재 자세를 보존**한다(`fcurve.preserve_current_pose`). 커브를 고치면 Blender 가 애니를 다시 평가해서 지워지기 때문.
- 실패는 한국어 `StudioError` 로만 알린다. 프로그램 오류(TypeError 등)는 잡지 않는다.
- 패널 문구는 짧은 한글, 버튼·파라미터 이름은 영어. 설명은 툴팁. `draw()` 안에서 데이터 쓰기 금지.
- Rig Studio 리그: FK 역할(`up_fk`·`lo_fk`·`end_fk`)은 그 팔다리가 FK 모드일 때만, IK 역할(`ik`·`pole`)은 IK 모드일 때만 대상. 모드는 그 프레임 값으로 판정.
- 회사명·캐릭터 이름을 어떤 파일에도 쓰지 않는다.

## 4. 알려진 문제·보류

1. **DEF `Skin_*Seg_03` 약 6e-4 차이 — Anim Studio 문제 아님.** Blender Spline IK 가 각도를 낮은 정밀도로 계산해 입력이 1e-6 만 달라도 한 칸(약 3.5e-4 rad) 튄다. Rig Studio `parts/limb.py` 마지막 Aim 이 Spline IK 본 tail 을 조준해서 드러남. 조준 대상을 구간 끝점 본으로 바꾸면 6.8e-5 로 줄어듦(메모리 실험). Rig Studio 수정은 HS 보류.
2. Rig Studio 자동 매칭(`sync.py`)은 `anim_studio_busy` 를 확인하지 않는다. 현재 모드 규칙으로 실측상 문제없음 → Rig Studio 수정 보류.
3. Toggle World Local 은 씬 데이터(변환 방향)를 바꾸지만 Undo 대상이 아님(00b 결정, Max 와 같음). 바꿀지는 HS 결정 대기.
4. 사이드바 2열에 긴 영어 이름이 잘림 → 00d 6번 + 00e 에서 해결 예정.

## 5. 검증 방법

- 테스트는 **새 Blender 를 따로 띄워서**만 돌린다(사용 중인 Blender 에 보내지 않음):
  `"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python-exit-code 1 --python anim_studio\tests\<파일>.py`
- 현재 통과: `blender_smoke`, `blender_fix_00c`, `blender_rig_studio`, `blender_fix_00d`, `blender_modes_00d`. 미완: `blender_icons_00d`(00d 6번 완료 기준).
- 실제 리그는 `Blender_Rig` 를 sys.path 에 넣고 `sys.dont_write_bytecode = True` 후 `from rig_studio import build; build.build()`. 자동 매칭까지 보려면 `from rig_studio import sync; sync.install()`.
- 열린 Blender 에서 Undo 를 잴 때: 스크립트로 부른 오퍼레이터는 Undo 단계를 스스로 쌓지 않는다. `ed.undo_push` 로 앞뒤 단계를 직접 쌓고 `ed.undo` 한 번. 안 그러면 Undo 가 테스트 준비 전까지 되돌아간다.
- 테스트 씬은 끝나면 지운다(씬·리그·카메라·액션). 열린 씬에 키·임시 객체를 남기지 않는다.
- 이중점검: 지시서와 코드만 주고 판단은 주지 않는다. 재현된 것만 진짜 문제로 분류.
